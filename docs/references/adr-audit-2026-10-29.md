# Audit complet des huit ADR

## Conclusion et règle de lecture

L'audit couvre les décisions, étapes de migration et critères de validation des
huit [[adr/README|ADR]]. Il ne prétend pas que tous leurs critères sont satisfaits.
Une obligation conditionnelle non déclenchée n'est pas transformée en défaut.
Les champs ont été examinés séparément : `status` décrit l'adoption d'une
décision ; `implementation` décrit sa réalisation, pas le volume de tests.

- **ADR-0001 : Proposed / partial**, au lieu de not-started : résolution des
  composants, topologie N=2 et préparation float existent réellement.
- **ADR-0002 : Proposed / partial** : la séquence N=2 est livrée, mais ses
  `IPass&` restent polymorphes. Les bindings float sont partiellement livrés ;
  leur absence totale était une affirmation obsolète.
- **ADR-0003 : Accepted / partial** : propriété et cycles de vie des tranches
  sont exercés ; tous les échecs de lecture/fermeture ne le sont pas.
- **ADR-0004 : Proposed / partial** : tranche float adoptée et vérifiée,
  pas adoption générale des layouts ; mesure des allocations non acquise.
- **ADR-0005 : Accepted / partial** : critère précisément non prouvé :
  coverage ON exécutée, ou rejet ciblé exécuté sur une toolchain non supportée.
  L'absence de Release ou de GPU matériel Linux n'est pas le motif du verdict.
- **ADR-0006 : Proposed / not-started** : protocole de mesure comparative non
  exécuté. Tests, pixels et identités ne constituent pas un benchmark.
- **ADR-0007 : Proposed / partial**, au lieu de not-started : la correction
  initiale C++23 est réalisée ; les clauses futures du cooker ne sont pas activées.
- **ADR-0008 : Accepted / verified**, dans la baseline Windows Debug adoptée ;
  Linux reste une preuve complémentaire distincte.

Ces conclusions conservent les statuts décisionnels faute d'une adoption globale
supplémentaire documentée, mais corrigent deux états d'implémentation périmés.
L'existence d'une tranche ne suffit pas à adopter silencieusement toute la cible.
Pour ADR-0007, `partial` qualifie la partie effectivement matérialisée du contrat,
pas un engagement de construire maintenant le cooker. ^[inferred]

## Méthode, preuves et applicabilité

Audit sur `main` à `3d3e508` : deux recherches indépendantes en lecture seule,
architecture et build, puis recoupement et consolidation par le lead. Les finales
publiques ont été récupérées par l'API native après défaut du collecteur d'équipe,
avec `finish=stop`, pagination épuisée et hashes ; aucune relance des auteurs.
Leur restitution est une source attribuée, pas une nouvelle exécution de tests.
Les obligations regroupées dans les remises sont décomposées ci-dessous.

Étiquettes : **PROUVÉ** = preuve exécutée existante et bornée ; **OBSERVÉ** = code
ou contrat lu, sans preuve d'exécution suffisante ; **PARTIEL** = parties acquises
et parties restantes nommées ; **NON EXÉCUTÉ** = expérience non établie ;
**NON IMPLÉMENTÉ** = cible absente dans le périmètre inspecté ; **N/A** = condition
non déclenchée ; **INCONCLUSIF** = preuve insuffisante pour trancher.

Les identifiants D/M/C suivent respectivement les paragraphes de décision,
migration et critères de chaque ADR. Ils servent à rattacher chaque obligation,
pas à ajouter des exigences produit.

- **E03** : `_meta/build-validation.json`, Windows x64 Debug/MSVC 19.44,
  toolset14.44, Conan2.12.2, 109/109 = 87 CPU + 22 OpenGL NVIDIA, coverage OFF.
  `_meta/session-2026-10-03-validation.json` décrit ensuite Shader→Pass, 122/122,
  sans transformer la population précédente en nouveau candidat.
- **E20** : `_meta/session-2026-10-20-pipeline-execution-path.json`,
  `fdbce15dcc05663cc58618a844d931b07b84750f`, 546/546 Windows Debug,
  477 CPU + 69 OpenGL ; décisions humaines de topologie/coexistence et ledger K.
- **E26** : `_meta/session-2026-10-26-stable-reader-cleanup.json`,
  `a96104c7aaeede7dd6915bfeac86f53565615114`, 555 normaux/555 ASan Windows,
  484 CPU + 71 GL ; échecs authentiques extraction/close non exercés.
- **E27** : `_meta/session-2026-10-27-prepared-float.json`,
  `3b1b1028dcd64ca46e0a359365ae096be1a38ac4`, 581 normaux/581 ASan Windows,
  506 CPU + 75 GL ; oracle pixel fixe, mutants, revues et limites RED conservés.
- **E29** : `_meta/session-2026-10-29-linux-qa.json`, runtime
  `78e7b74989dd463cddf14080916e03b60405640d`, six configurations à 589/589,
  513 CPU + 76 OpenGL ; contrôleur `f58a49f4261e018749c59b0d8aab9dd7e85ba53e`,
  quatre nouveaux runs WSL/CI à 589/589 avec 169 hashes dont 20 shaders.
  Windows est réutilisé par identité, pas rebaptisé exécution du contrôleur renforcé.

Le lead a vérifié par comparaison Git qu'aucune différence ne sépare le runtime
qualifié du HEAD d'audit pour `ARTIST/`, `test-datas/`, CMake, presets, Conan et
workflow ; aucune différence des cinq scripts contrôlés depuis `f58a49f`.
Cela établit l'identité aux chemins déclarés, pas une nouvelle campagne.
Les hashes des huit ADR avant édition et ces contrôles sont dans `inputs.json`.

## ADR-0001

[[adr/0001-resolution-multi-etapes|Contrat source]]. Adoption : formalisation
demandée le 3 octobre ; pas d'adoption globale supplémentaire établie.

- **D1 — Structure compile-time : OBSERVÉ.** `Pipeline<API,PROFILE>` sélectionne
  des composants par concepts/`if constexpr` ; `ClosedExecution` fixe deux membres.
  Cela ne rend pas concrètes les passes référencées.
- **D2 — Link-time, instanciations/LTO : NON EXÉCUTÉ pour les effets machine.**
  Pas d'inspection d'inlining/dévirtualisation ou mesure liée au contrat. Un flag
  ne suffirait pas ; aucune amélioration machine n'est validée par cet audit.
- **D3 — Préparation/cook : PARTIEL.** `prepareFloatUniform` résout nom/type
  après link, à runtime de préparation (E27), pas dans un cooker absent.
- **D4 — État vivant runtime : OBSERVÉ.** Contextes, curseur et objets driver
  restent des données runtime ; aucune scène ou valeur d'asset encodée en type
  n'est ajoutée par les tranches examinées.
- **D5 — Objets driver et invalidation : PROUVÉ sur la tranche float.**
  `PreparedFloatUniform.hpp` valide programme/témoins/générations ; son contrat
  exclut relink/delete externe, concurrence et fenêtre détruite. Pas de plan global.
- **D6 — Axes et bornes de spécialisation : PARTIEL.** API/PROFILE et N=2 sont
  explicites ; coût de build/code-size NON EXÉCUTÉ. Scene-to-code non engagé : N/A.
- **M1 — Chaîne actuelle et classification des entrées : PARTIEL.** Ledger K,
  [[architecture/closed-execution-pattern|motif fermé]] et préparation float
  explicitent leurs responsabilités (E20/E27) ; pas d'inventaire transversal du moteur.
- **C1 — Binding times, invalidations, owners : PROUVÉ par tranches, pas global.**
  Structure N=2, emprunts à owners survivants et résolution après link documentés ;
  les tranches ne constituent pas un plan cook/runtime général.
- **C2 — Types valides/invalides : PROUVÉ au périmètre des contrats compilés.**
  Concepts Pipeline/Uniform et contraintes des tranches ; E20/E27/E29, pas tous
  les futurs layouts ou profils possibles.
- **C3 — Comportement CPU/rendu/erreurs : PROUVÉ selon les oracles distincts.**
  Ordre CPU et état GL (E20), pixels du float (E27), non-régression E29.
- **C4 — Appels directs et gain : N/A comme revendication ; NON EXÉCUTÉ comme mesure.**
  Aucun gain validé. Le virtuel de `IPass::use()` demeure dans la source.

Verdict : **Proposed / partial** ; `not-started` ne décrivait plus la réalisation.
Cela ne signifie ni exécution entièrement statique ni adoption de toute l'ADR.

## ADR-0002

[[adr/0002-preparation-et-execution-specialisee|Contrat source]]. E20 adopte la
topologie N=2 et sa coexistence, pas la cible terminale tuple/passes concrètes.

- **D1 — Préparation flexible et bindings : PARTIEL.** API par noms et validation
  présentes ; préparation float E27, pas de plan dense général.
- **D2 — Exécution par passes concrètes/composition directe : NON IMPLÉMENTÉ.**
  `ClosedExecution.hpp:32–51` stocke deux `IPass<API>&`, pas des passes concrètes
  ou un tuple ; la séquence est littérale mais les appels restent polymorphes.
- **D3 — Sélection par configuration/pass/lot, boucle monomorphe : PARTIEL.**
  Sélection de composants par passe observée ; aucun kernel de lot ou coût amorti
  général démontré. N=2 ne prouve pas ce déplacement de frontière.
- **D4 — Données de frame compactes, allocations/lookups : PARTIEL.**
  Le float préparé évite la recherche répétée de nom/type ; pas de modèle général
  spans/records de frame ni mesure d'allocation.
- **D5 — Graphe, dépendances variables et invalidation : N/A.** Render graph non
  introduit ; aucun planning/barrière universel n'est déclaré implémenté.
- **M1 — Caractériser use/useNext/reset, indices/erreurs : PROUVÉ.** E20 et ledger K,
  tests CPU et `ProgramTests.cpp` ; les états et erreurs ne sont pas fusionnés.
- **M2 — Introduire le chemin et transmettre l'ownership : PARTIEL.**
  Type fermé N=2 livré, emprunts non-owning aux passes possédées ; la composition
  terminale concrète reste absente. L'ancien addendum est borné à ce prototype.
- **M3 — Préparer des bindings : PARTIEL depuis E27.** `PreparedFloatUniform`
  existe ; ce n'est plus « non implémenté » sans réserve, mais aucun raccordement
  général au chemin N=2 n'est démontré.
- **M4 — Migrer les consommateurs/retirer une compatibilité : NON IMPLÉMENTÉ.**
  Le type coexiste ; les usages retrouvés sont les tests du nouveau type. Aucun
  retrait de compatibilité requis n'est entrepris sans consommateurs traités.
- **C1 — Ordre et effet voulus : PROUVÉ au périmètre N=2.** Oracles CPU de séquence
  et readback de programme GL sont complémentaires (E20/E29).
- **C2 — Erreurs de configuration/exécution : PROUVÉ sur la tranche.** Premier
  échec interrompt la suite, exceptions préservées, moved-from des passes gardé.
- **C3 — Stockage et dispatch : OBSERVÉ directement.** Corps et références Serena,
  puis grep exact des usages/tests ; les références LSP seules étaient incomplètes.
- **C4 — Image équivalente du chemin migré : NON EXÉCUTÉ.** Le readback de programme
  ne remplace pas un oracle d'image ; celui du float n'est pas une image comparative
  du chemin ClosedExecution.
- **C5 — Comparaison ancien/runtime-lots/statique, coût code/build : N/A sans gain
  revendiqué ; expérience NON EXÉCUTÉE.** Aucun gain n'est imputé à ce prototype.

Verdict : **Proposed / partial**, avec correction du contexte partagé historique
et de l'affirmation d'absence totale des bindings.

## ADR-0003

[[adr/0003-ownership-et-lifetime-cpu-gpu|Contrat source]]. Adoption explicite du
3 octobre ; les paragraphes historiques gardent leurs candidats et limites.

- **D1 — Owners identifiables, partage justifié : PROUVÉ sur les tranches.**
  Pipeline/Pass/Shader/Uniform/Attribute et leurs collections ont des owners uniques ;
  les getters et `ClosedExecution` empruntent. Pas de généralisation à toute ressource future.
- **D2 — Opérations non-owning et rétention asynchrone : OBSERVÉ/PROUVÉ.**
  Composants `on(C&)`, getters empruntés, owners devant survivre à la chaîne N=2 ;
  aucune rétention asynchrone nouvelle à qualifier.
- **D3 — Copie/move/vide/échec/free répété : PROUVÉ selon les tranches.**
  Shader→Pass, loaded-owner move, Pipeline/F7 puis suites courantes ; nettoyage
  avant transfert et garantie de base sur échec, pas rollback natif global.
- **D4 — Invalidation et générations si nécessaire : PROUVÉ pour float.**
  Mutations suivies, retraits, destructions et incarnations révoquent l'emprunt
  préparé (E27). Les références nues conservent leurs préconditions d'owner vivant.
- **D5 — Destruction contexte/thread/backend : PROUVÉ pour les cycles GL testés.**
  Un contexte compatible courant reste une précondition. Fences et retraite d'une
  API explicite future : N/A, pas motif artificiel pour conserver partial.
- **D6 — Destructeurs non-throwing et ownership de device optionnel : OBSERVÉ.**
  Les destructeurs concrets ne redescendent pas vers un override de base détruite.
  Un cleanup levant peut terminer le processus ; aucune garantie de récupération
  hors préconditions n'est inventée. Owner de device futur non introduit : N/A.
- **D7 — Reload strict B : PROUVÉ.** Handle vivant rejeté avant `glCreate*`,
  free explicite avant rechargement ; pas de remplacement transactionnel adopté.
- **D8 — Free du pass et du shader distincts : PROUVÉ/documenté.** Libérer le
  programme ne libère pas les shaders ; le cycle complet et le comportement
  partiellement engagé restent ceux des tranches, pas une atomicité globale.
- **M1 — Création→emprunts→dernières utilisations→destruction : PARTIEL.**
  Cycles et ordre explicités pour les tranches et testés CPU/GL ; pas une preuve
  universelle de tous les échecs de préparation.
- **M2 — Signatures internes puis adaptateurs : PROUVÉ sur la migration livrée.**
  Fin du partage implicite des contextes, bases d'assignation protégées et
  composants emprunteurs ; historique partagé explicitement daté.
- **M3 — Copies de wrappers/contextes partageant un handle : PROUVÉ sur les owners
  migrés.** Non-copiables, moves et destinations chargées couverts ; aucune
  duplication de propriété native permise par la tranche.
- **C1 — Création échouée à chaque étape et nettoyage : PARTIEL.** Échecs de
  création/compilation/link/détachement exercés selon les dossiers ; E26 conserve
  explicitement les échecs authentiques extraction/fermeture non exercés. Ce manque
  concret de preuve des chemins de préparation empêche une clôture exhaustive.
- **C2 — Move/destruction/accès périmé/free répété : PROUVÉ au périmètre testé.**
  Tests lifetime, moved-from et révocation float ; E27 puis E29 normal/ASan.
- **C3 — Usage asynchrone introduit, survie et IDs sans alias : N/A pour un nouveau
  système asynchrone.** Les préconditions GL existantes restent explicites ; aucun
  système de frame en vol ou nouveau backend n'est promis.
- **C4 — CPU/sanitizers supportés et driver : PROUVÉ sur les campagnes actuelles.**
  E29 Windows/NVIDIA et Linux/llvmpipe, normal/ASan, sans détection de fuites. Cela
  ne réexécute pas rétroactivement les candidats historiques dont ASan manquait.

Verdict : **Accepted / partial**, pour les limites de preuve actuelles nommées,
pas pour exiger une RAII exhaustive ou une API future absente du contrat engagé.

## ADR-0006

de protocole ; aucune campagne comparative exécutée ou adoption globale retrouvée.

- **D1 — Baseline, mêmes données/travail/API/qualité : PARTIEL comme prérequis.**
  Baselines de tests E20/E27/E29 identifiées ; aucune comparaison de coût équivalente.

  Acquis réutilisable ; il ne réalise pas le protocole performance.

  Le type N=2 n'est pas la mesure de cette comparaison.
- **M2 — Prototype scene-to-code : N/A, piste conditionnelle non engagée.**
  Pas un chantier requis pour accepter la QA actuelle.
